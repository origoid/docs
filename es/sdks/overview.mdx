Publicamos SDKs oficiales para los tres lenguajes más usados por los
clientes de OrigoID. Los tres se generan automáticamente desde la misma
especificación OpenAPI, así que siempre cubren todos los endpoints y
permanecen sincronizados con el API. No hay variantes mantenidas por la
comunidad — estos son los clientes oficiales y soportados.

## Por qué usar un SDK en lugar de HTTP crudo

Puedes llamar a nuestros endpoints REST con `curl`, `fetch`, `requests`,
o `net/http`. Los SDKs agregan:

- **Modelos tipados de request y response** — tu IDE autocompleta cada
  campo, tu compilador detecta typos, tu linter marca valores requeridos
  faltantes.
- **Base URL embebido** — `https://api.origoid.com` está integrado. No
  hay nada que configurar más allá del API key.
- **Manejo del header de auth** — pasa tu key una sola vez al construir.
- **Reintentos automáticos** — errores `5xx` transitorios y de red se
  reintentan con backoff exponencial (configurable por llamada).
- **Enums fuertemente tipados** — códigos `type`, `cancellationStatus`,
  `riskLevel`, etc. aparecen como enums o uniones de strings, nunca como
  strings crudos.
- **Errores útiles** — un `401 UNAUTHORIZED` lanza `UnauthorizedError`
  con el envelope ya deserializado, no un `HTTPError` genérico.

Si sólo necesitas llamar un endpoint ocasionalmente desde un script,
`curl` es suficiente. Para cualquier integración productiva recomendamos
fuertemente el SDK.

  <Card title="TypeScript / Node" icon="js" href="/es/sdks/node">

## Matriz de paridad

| Capacidad | Node | Python | Go |
| --- | :---: | :---: | :---: |
| Los 19 endpoints | ✅ | ✅ | ✅ |
| Llamadas async (`await`) | ✅ nativo | ✅ via `AsyncOrigoID` | ✅ via `context.Context` |
| Llamadas sync | n/a (JS es async) | ✅ via `OrigoID` | ✅ (context puede ser `Background`) |
| Base URL embebido | ✅ | ✅ | ✅ |
| Reintentos automáticos | ✅ (2 por default) | ✅ | ✅ |
| Override de timeout por llamada | ✅ | ✅ | ✅ |
| Envelope tipado (`status`, `type`, `data`) | ✅ | ✅ Pydantic | ✅ struct |
| Errores tipados (401, 429) | ✅ | ✅ | ✅ |
| Soporte navegador | Usa Node SDK o llama el API directo con CORS configurado ([pide allowlist CORS](/es/authentication#integraciones-desde-navegador-cors)). | n/a | n/a |

en cada release del API.

## Versionado

Los SDKs siguen [semver](https://semver.org/lang/es/).

- **Major** (`1.0.0` → `2.0.0`) — cambios incompatibles en la shape del
  SDK (raro; sólo cuando el OpenAPI subyacente rompe). Siempre acompañado
  por una guía de migración en las release notes.
- **Minor** (`0.1.0` → `0.2.0`) — endpoints nuevos, campos nuevos,
  helpers nuevos. Compatible hacia atrás.
- **Patch** (`0.1.0` → `0.1.1`) — fixes de bugs, actualización de
  dependencias, mejoras de docs.

Mientras los SDKs están en `0.x.y` seguimos la convención de subir la
versión **minor** para cambios incompatibles (según semver pre-1.0) y la
patch para todo lo demás. Cuando un SDK llega a `1.0.0` aplican las
reglas semver clásicas.
