Algunas consultas al IMSS tardan más de lo que conviene esperar con una petición HTTP abierta, por eso se ofrecen como endpoints **asíncronos**: envías la petición con un objeto `webhook` y te entregamos el resultado en tu URL cuando está listo.

| Endpoint | Créditos | Resultado |
|---|---|---|
| [Get NSS (Async)](/es/api-reference/social-security/get-nss-async) | 2 | Se entrega a tu webhook |
| [Employment Status (Async)](/es/api-reference/social-security/employment-status-async) | 2 | Se entrega a tu webhook |
| [Contribution Weeks](/es/api-reference/social-security/contribution-weeks) | 3 | Se entrega a tu webhook, con consulta de respaldo por 24 horas |

## Cómo funciona

1. **Crea la petición.** Haz `POST` con la consulta y un objeto `webhook`. La API responde de inmediato con `type: ACCEPTED` y un `transactionId`. Aceptar la petición no se cobra (`billable: false`).
2. **Recibe el resultado.** Cuando la consulta se resuelve, enviamos un `POST` HTTP a tu `webhook.url`. El cuerpo es el [envelope](/es/envelope) estándar, con el **mismo `transactionId`** del paso 1.

Petición:

```json
{
  "curp": "RATL850312HDFMRS07",
  "webhook": {
    "url": "https://your-domain.com/hooks/origoid",
    "headers": {
      "Authorization": "Bearer YOUR_WEBHOOK_TOKEN"
    }
  }
}
```

Respuesta inmediata:

```json
{
  "status": "OK",
  "type": "ACCEPTED",
  "message": "Request accepted, result will be sent to the webhook",
  "data": null,
  "transactionId": "322e6c8b-0124-5c84-95db-4da04842d0da",
  "processedAt": "2026-03-15T19:23:30-06:00",
  "billable": false
}
```

Si la petición no es válida, recibes `INVALID_REQUEST` de inmediato en lugar de `ACCEPTED`, y nunca se cobra:

```json
{
  "status": "ERROR",
  "type": "INVALID_REQUEST",
  "message": "Validation failed",
  "data": null,
  "errors": [
    {
      "field": "curp",
      "code": "INVALID_FORMAT",
      "message": "curp is not a valid CURP"
    },
    {
      "field": "nss",
      "code": "INVALID_FORMAT",
      "message": "Invalid NSS format (must be 11 digits)"
    },
    {
      "field": "webhook",
      "code": "MISSING_REQUIRED_FIELD",
      "message": "must have required property 'webhook'"
    }
  ],
  "transactionId": "6117e20e-ea53-5424-87a9-da7576d4cd12",
  "processedAt": "2026-10-26T11:20:00-06:00",
  "billable": false
}
```

## El objeto `webhook`

| Campo | Requerido | Descripción |
|---|---|---|
| `url` | Sí | URL pública `http` o `https` que recibe el resultado. |
| `headers` | No | Nombres y valores de headers que agregamos a la petición a tu webhook — por ejemplo, tu propio token, para que tu endpoint autentique la llamada. |

## Tu endpoint de webhook

- Recibe un `POST` HTTP con cuerpo JSON (`Content-Type: application/json`) y los headers que configuraste.
- Responde con cualquier status `2xx` en cuanto recibas el cuerpo, y procésalo después.
- Hazlo idempotente: el mismo resultado puede llegar más de una vez, así que usa `transactionId` para descartar duplicados.

## Intentos de entrega

Intentamos entregar cada resultado hasta **3 veces**: de inmediato, y luego 1 minuto y 5 minutos después del intento fallido anterior. Un intento falla cuando tu endpoint no responde con un status `2xx` en menos de 10 segundos (no seguimos redirecciones). Después del tercer intento fallido, el resultado ya no se vuelve a enviar.

La disponibilidad de tu endpoint de webhook es tu responsabilidad: los créditos se cobran cuando el resultado se resuelve, lo reciba o no tu endpoint. En Contribution Weeks todavía puedes consultar el resultado durante 24 horas (ver [Respaldo de Contribution Weeks](#respaldo-de-contribution-weeks)).

## Cobro

Los créditos se cobran una sola vez, cuando el resultado se resuelve, con la misma regla que el resto de los endpoints (ver [Créditos](/es/credits)): `billable: true` cuando la consulta se realizó — aunque el resultado sea negativo, como `CURP_NOT_FOUND` — y `false` en fallas técnicas. El campo `billable` del cuerpo que recibe tu webhook indica cuál aplica.

### Contribution Weeks

Cómo leer `data` (`SUCCESS` e `INACTIVE_EMPLOYMENT`):

- Campos oficiales, tomados del documento del IMSS: `nss`, `personalInfo`, `contributionWeeks` (`total` = `contributed` − `discounted` + `reinstated`), `employmentHistory` (un renglón por empleo, del más reciente al más antiguo) y `reportDetails` (`folio`, `issueDate`, `digitalSeal`, …). `files[0]` es el PDF oficial en base64 (recortado en los ejemplos).
- El empleo vigente es el renglón de `employmentHistory` con `endDate: null`; en `INACTIVE_EMPLOYMENT` no hay ninguno.
- Todo lo calculado vive en `derivedSignals` — `currentStatus`, `jobTenure` (meses), `stability`, `salary` y `salaryTimeline`. Son hechos, no un score de crédito.
- Los salarios (`baseSalary`, `*Salary`) son el salario base de cotización (SBC) **diario**; el equivalente mensual es SBC × 30.44. `salaryAtLegalCap: true` significa que el salario llegó al tope legal (25 UMA), así que el ingreso real puede ser mayor.
- Todos los campos siempre están presentes; los que no aplican vienen en `null`.

## Respaldo de Contribution Weeks

Si tu webhook no pudo recibir un resultado de Contribution Weeks, consúltalo durante 24 horas con [Contribution Weeks Result](/es/api-reference/social-security/contribution-weeks-result) (gratis), enviando el `transactionId`:

```json
{
  "transactionId": "975cf12f-f270-51cc-9037-d710134940c9"
}
```

Responde `RESULT_FOUND` (con el envelope original del resultado dentro de `data`), `RESULT_PENDING` o `RESULT_EXPIRED`. Úsalo solo como respaldo: el resultado siempre se envía a tu webhook.
